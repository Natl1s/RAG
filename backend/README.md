# Backend — FastAPI-сервис чат-бота «Юридический ассистент ПСБ»

Сервис принимает одно новое сообщение пользователя и `conversation_id`,
хранит историю диалога в памяти процесса и отдаёт ответ агента потоком SSE.

История живёт в памяти процесса: при рестарте контейнера диалоги теряются.
Для нескольких воркеров uvicorn это тоже не сработает — у каждого процесса
свой словарь.

## Файлы

- `main.py` — приложение, HTTP-эндпоинты, память диалогов, SSE;
- `test_main.py` — pytest-тесты потока и памяти;
- `requirements.txt` / `requirements-dev.txt` — зависимости;
- `docker-entrypoint.sh` — входная точка контейнера: по умолчанию ничего не
  скачивает, запускает `uvicorn`; загрузка RusLawOD включается
  `DOWNLOAD_DATASET=true`.

## Запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -r requirements.txt
cd backend
uvicorn main:app --reload --port 8000
```

Нужен файл `.env` в корне репозитория (см. `.env.example`): `LLM_BASE_URL`,
`LLM_API_KEY`, `LLM_MODEL`. Эмбеддинги и реранкер ходят на тот же `LLM_BASE_URL`,
модели задаются через `EMB_MODEL` и `RERANKER_MODEL`. Значения по умолчанию в
`docker-compose.yml` — `Qwen/Qwen3-Embedding-0.6B` и `Qwen/Qwen3-Reranker-0.6B`
(доступны на SiliconFlow). Платформа подставляет свои значения: переменные
окружения имеют приоритет над `.env`.

Документация — http://127.0.0.1:8000/docs.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/` | описание сервиса |
| `GET` | `/api/health` | `{"status":"ok","agent":true,"retrieval":"hybrid","conversations":0}` |
| `POST` | `/api/chat` | поток SSE: `meta` → `token*` → `done` |
| `GET` | `/api/conversations/{id}` | история диалога |
| `DELETE` | `/api/conversations/{id}` | сброс диалога |
| `POST` | `/api/conversations/{id}/close` | сигнал «вкладка закрылась» |

### `POST /api/chat`

```json
{ "query": "А до какого числа её вносить?", "conversation_id": "9f1c…" }
```

`conversation_id` необязателен: если его нет, сервер сгенерирует свой и вернёт
в первом событии. Допустимы латиница, цифры и дефис, 8–64 символа.

Ответ — `text/event-stream`:

```
data: {"type": "meta", "conversationId": "9f1c…"}

data: {"type": "token", "text": "Арендная плата "}

data: {"type": "token", "text": "вносится до 5-го числа."}

data: {"type": "done", "answer": "…", "latencyMs": 4210}

data: [DONE]

```

При ошибке агента вместо `token*` приходит одно событие:

```
data: {"type": "error", "message": "…"}
```

### Как собирается запрос к агенту

История хранится как список реплик `{"role", "content"}`. Перед вызовом она
обрезается (не больше 8 реплик и 6000 символов) и склеивается в строку:

```
Пользователь: Какая арендная плата по договору с ООО «Северный Склад»?
Ассистент: 450 000 рублей в месяц, п. 3.1…
Пользователь: А до какого числа её вносить?
```

Агент разбирает эту строку сам (`agents/dialog.py`): всё до последней реплики
пользователя — история, последняя реплика — вопрос. Двоеточия в метках ролей
внутри пользовательского текста заменяются на `∶`, чтобы нельзя было
подделать реплику ассистента.

### Жизненный цикл диалога

- `conversation_id` генерирует фронтенд и хранит в `sessionStorage`: у каждой
  вкладки свой диалог, который переживает F5;
- при закрытии вкладки браузер шлёт beacon на `/close`; сервер помечает диалог
  и удаляет его через 15 секунд. Если страница перезагрузилась, следующий
  запрос с тем же id отменяет удаление;
- чтобы отличить перезагрузку от закрытия, фронтенд передаёт метку времени
  браузера (`ts`, миллисекунды). Beacon, пришедший после запроса новой
  страницы, отбрасывается как устаревший (`{"status":"stale"}`);
- диалог без запросов удаляется через 30 минут;
- одновременно хранится не больше 500 диалогов, самый старый вытесняется.

## Docker

Одна команда из корня репозитория:

```bash
docker compose up --build
```

Дальше — http://localhost:8080. Ничего доустанавливать и докачивать вручную
не нужно:

- зависимости ставятся при сборке образа;
- корпус `dataset/result_chunks.csv` копируется в образ;
- фронтенд собирается в том же `docker compose up` и проксирует `/api`
  на бэкенд;
- значения `LLM_*` Compose берёт из `.env` рядом с `docker-compose.yml`.

Если `.env` нет, контейнер всё равно поднимется, но на вопрос ответит
ошибкой «На платформе отсутствует API-ключ».

Тяжёлые загрузки выключены по умолчанию. Включить при необходимости:

```bash
DOWNLOAD_DATASET=true docker compose up --build   # скачать RusLawOD в том
```

Сервис стартует даже при недоступном embedding-эндпоинте: в этом случае он
логирует ошибку и собирает BM25-индекс (поле `retrieval` в `/api/health`
показывает `hybrid` или `bm25`). Так же он ведёт себя, если внешний реранкер
вернул ошибку — реранкер отключается на лету, поиск продолжается.

В образ попадают `backend/`, `rag/`, `script/`, `agents/` и готовый корпус
чанков; проект датасета при `DOWNLOAD_DATASET=true` живёт в томе
`psb-dataset`.

## Куда подключать реальные модели

RAG и агент собираются в `warm_up()` (`main.py`): читается
`dataset/result_chunks.csv`, строится индекс, создаётся `AgentService` через
`build_local_service()`. Менять логику ответа нужно в агенте (`agents/`), а не
в HTTP-слое. Формат событий `meta` / `token` / `done` и фронтенд при этом
менять не нужно.
